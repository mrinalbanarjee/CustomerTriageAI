Triage & Recon Assistant high-level design

Recon flow

Each L2 gets its own recon source and recon collection. Today only Loan Admin has one.

  1. R1

    Splunk webhook Current

    When Splunk raises an alert, it calls the webhook, which stores the alert in the Splunk Alert DB.

  2. R2

    Loan Admin Recon Current

    It pulls issue details from the audit tables and the Splunk Alert DB through the GET API, reconciles them, and stores the recon details in the LoanAdminRecon collection through the POST API.

    Future: a recon flow for each other L2, with its own source and collection.

  3. R3

    Reconciliation Current

    The Reconciliation view in the dashboard shows the recon records from each L2’s recon collection. Today that is LoanAdminRecon.

Triage flow

Letters mark the two ways into triage, and numbers match the diagram. Lines marked Future are planned.

  1. A

    LLM Scheduler Current

    On a schedule it pulls recon records from LoanAdminRecon through the API, runs the triage, and stores the results in the Loan Admin TriageRecords collection through the API.

    Future: it pulls from the other L2 APIs and stores TriageRecords for each other L2.

  2. B

    Triage chatbot Current

    A user asks about an issue in the dashboard’s chatbot, which serves each L2 and today covers only Auto Loan Admin. It first looks for an existing triage record and answers from it. If the issue is new, it runs the triage and saves the result.

  3. 1

    Classify Current

    The LLM matches the issue to an L2 and the L1 component at fault with a vector DB search, which runs on ChromaDB today. Today that is Auto Loan Admin › Loan Boarding.

    Future: Tachyon as the vector DB, and more L1s such as Statement.

  4. 2

    Triage by runbook Current

    It follows that component’s runbook, kept in Confluence or as a prompt, and queries the audit tables at each step.

    Future: Splunk log searches with queries the LLM writes.

  5. 3

    Build recommended actions Current

    It stores the triage record in the TriageRecords collection for its L2. Each record holds several recommended actions: today a Mongo reprocess script, an Alfa update script in Python or a Jira defect.

    Future: ServiceNow incidents and Alfa cases.

  6. 4

    Test in a lower environment Current

    On any triage record, in Triage records or the chatbot, a person picks an action and an environment such as UAT and submits. The remediation API queues a run, the test runner applies the action there and checks the result, and the outcome shows on the record. Today it tests Mongo reprocess scripts and Alfa update scripts.

    Future: testers for Jira defects, ServiceNow incidents and Alfa cases.

  7. 5

    Deploy to prod Future

    From the same record, a person deploys once a test has passed. The remediation API raises a ServiceNow change through the IDP portal with the gameplan and test script attached, and the fix goes to production under that change.
