Triage & Recon Assistant high-level design

Step by step

Letters mark the two ways into triage, and numbers match the diagram. Lines marked Future are planned.

  1. A

    Background service Current

    It pulls Splunk alerts and sync-failure records from the audit tables in the database, each keyed by account number, ECN or third-party ID, and triages every new issue.

  2. B

    Triage chatbot Current

    A user asks about an issue in the web UI’s chatbot, which serves each L2 and today covers only Auto Loan Admin. It first looks for an existing triage record and answers from it. If the issue is new, it runs the triage and saves the result.

  3. 1

    Classify Current

    The LLM matches the issue to an L2 and the L1 component at fault with a vector DB search, which runs on ChromaDB today. Today that is Auto Loan Admin › Loan Boarding.

    Future: Tachyon as the vector DB, more L1s such as Statement, and the Customer Communication and Recovery L2s.

  4. 2

    Triage by runbook Current

    It follows that component’s runbook, kept in Confluence or as a prompt, and queries the audit tables at each step.

    Future: Splunk log searches with queries the LLM writes.

  5. 3

    Build remediation actions Current

    It saves the triage record and its remediation actions to the one MongoDB collection that both ways in share. Today an action can be a Mongo reprocess script, an Alfa update script in Python or a Jira defect.

    Future: ServiceNow incidents and Alfa cases.

  6. 4

    Test in a lower environment Current

    On any triage record, in Triage records or the chatbot, a person picks an action and an environment such as UAT and submits. The remediation API queues a run, the test runner applies the action there and checks the result, and the outcome shows on the record. Today it tests Mongo reprocess scripts and Alfa update scripts.

    Future: testers for Jira defects, ServiceNow incidents and Alfa cases.

  7. 5

    Deploy to prod Future

    From the same record, in either feature, a person deploys once a test has passed. The remediation API raises a ServiceNow change through the IDP portal with the gameplan and test script attached, and the fix goes to production under that change.
